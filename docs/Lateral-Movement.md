### T1570 LATERAL TOOL TRANSFER 
This rule detects instances where an attacker transfers malicious tools, scripts, or executables across internal systems over network shares. Attackers heavily rely on this technique during the lateral movement phase to move payloads, credential dumpers, or remote access tools from a compromised host to a newly targeted internal system.

The rule continuously monitors Windows Security EventID 5145 (A network share object was accessed). By filtering for dangerous and actionable file extensions (such as .exe, .dll, .ps1, .bat, .vbs, etc.) inside the RelativeTargetName field, the rule isolates code transport activities. Furthermore, it explicitly searches for %%4417 (WriteData/AddFile) or %%4418 (AppendData/AddSubdirectory) access rights within the AccessList field, effectively eliminating the noise generated by simple file read operations and focusing exclusively on file modification or creation events on network shares.

Catching lateral tool transfers in real-time is crucial to short-circuiting the attacker's operational pipeline. Intercepting a malicious payload at the moment it is dropped onto an internal share—before it can be triggered via scheduled tasks, remote services, or WMI—allows defenders to isolate the source host, prevent wide-scale network compromise, and contain ransomware or data exfiltration campaigns.

### T1021.002 REMOTE SERVICES: SMB/WINDOWS ADMIN SHARES (T1021.002) - PSEXEC LATERAL MOVEMENT CHAIN

This rule detects advanced lateral movement attacks that leverage Windows Administrative Shares (ADMIN$ or C$) combined with malicious service installations to execute remote commands. Attackers and frameworks like Impacket (psexec.py) heavily exploit administrative shares to drop an executable payload and immediately register it as a system service to gain an interactive SYSTEM shell on target hosts.

The analytics engine correlates two distinct log sources over a strict 2-minute time window on the same asset:

    Windows Security EventID 5145: Tracks an executable file (.exe) being written directly to an administrative network share (e.g., ShareName="\\*\ADMIN$").

    Windows System EventID 7045: Tracks the immediate installation of a new Windows service pointing to that exact dropped binary location (e.g., %systemroot%\<payload>.exe).

This correlation is highly effective because it maps the actual attack chain. Isolated admin share writes or service creations might occasionally happen during legitimate patch deployments, but when an executable is written to ADMIN$ and executed as a service within 120 seconds on the exact same host, it represents a definitive signature of a PsExec-style lateral movement sequence.
